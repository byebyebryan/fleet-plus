# Fleet Plus first edition

Accepted direction, 2026-10-23: keep six independent source repositories, add one
meta repository and one shared site. The user selected **Fleet Plus** as the name
and authorized repository creation in ~/code, implementation, commits and pushes
as completed checkpoints. Site publication and repository metadata are part of
the reviewed documentation/presentation delivery.

## Product and content design

The shared homepage gives brief ecosystem orientation, then features Agent Observer
and its dashboard example prominently. Host access, native TUI entry and tmux
management remain independent entry points. Agent Observer has a complete product
page; all six repository homepage links lead directly to their own product pages.

First edition: shared homepage; six product pages; setup-choice, architecture and
dated compatibility guides. Component installation/API/CLI docs remain canonical
in their owner repositories. Cross-project narrative belongs here. Historical
plans/receipts keep their existing paths and original scopes.

The public site uses https://dev.byebyebryan.com/fleet-plus/ through project GitHub
Pages. It inherits the portfolio domain; the project does not change DNS or the
parent site's domain. Use a small static build, accessible shared navigation,
responsive layouts, useful interaction with a static equivalent, canonical/share
metadata, a sitemap and an explicit public file inventory.

## Checkpoints

1. Establish this repository, catalog and ownership decisions; commit and push.
2. Reconcile current READMEs, documentation indexes/roadmaps and development guides
   across the six components. Correct published status, retired write/active paths,
   native provider scope and independent pins. Preserve original historical evidence.
3. Build the ten-page site, using existing public native-rendered dashboard and
   Rofi media with source revisions, hashes and clear sample-data captions.
4. Update the personal portfolio in its existing order and add a discoverable notes
   index plus two articles: the native-runtime pivot and read-only cross-host state.
5. Run owning source gates, site/link/content tests and isolated browser checks;
   publish source, GitHub descriptions/topics/homepages and Pages. Verify exact-head
   hosted checks, public metadata, all public pages/assets and actual served bytes.

## Acceptance

- Reader journeys work from portfolio, each component repo, shared site and articles.
- Observer's local core remains Mesh-free; optional networking supplies delivery.
- Native managers own conversations; Agent Plus owns environment/window entry.
- Working-set includes active membership; Observer writes and standalone active-only
  delivery remain retired. Full diagnostics and generic tmux actions stay supported.
- Directional routing is illustrated accurately without proposing reverse access.
- Compatibility claims link to dated owner evidence; managed manifests remain
  authoritative for installed roles. Carbon partial membership is unresolved and
  cannot be represented as a complete empty set or a universal fleet pass.
- Experimental delta/view-feed/WSS adoption is not implied by site publication.
- Local links/anchors/assets, metadata, keyboard controls, mobile widths, reduced
  motion and no-JavaScript reading work. Presentation examples are clearly labeled.
- Source/release/runtime pins, historical evidence, research worktrees, native
  sessions and unrelated work are preserved.

## Ownership decision

Keep repositories separate. Fleet Plus supplies a shared reading and presentation
home, not a unified runtime release. Revisit source consolidation only with evidence
of recurring coordination cost. Codex Plus and hardware dashboards are related
projects/consumers with independent source and delivery owners.
